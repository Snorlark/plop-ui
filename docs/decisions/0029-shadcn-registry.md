# 0029: A shadcn-compatible registry, built on the npm packages

Many React developers (and AI coding tools) install UI with the shadcn CLI. Similar libraries spread by plugging
into it (8bitcn). PlopUI now serves a registry at `plopui.com/r/*.json`, so `npx shadcn add <url>` works.

- **Items install the npm packages, not copies of the library.** PlopUI's components share internals (the sticker
  physics, seeded wobble, token CSS, Buddy), so copying one component would drag in a dozen files and freeze it in
  every app. Each item lists `@plop-ui/react` and `@plop-ui/fonts` as dependencies; fixes keep flowing through npm.
- **`plop-setup`** adds `components/plop/plop-provider.tsx` (styles + fonts + `PlopProvider`) once; every other
  item depends on it.
- **One item per component page**, generated by `apps/docs/scripts/build-registry.mjs` from the code example in
  `app/_site/registry.ts`, so the registry can't drift from the docs. Snippets that are illustrative on the page
  (placeholders, sample data in comments) get a working file in `registry/examples/<slug>.tsx`.
- **Blocks** (`registry/blocks/*.tsx`): whole screens (settings panel, sign-up card, empty state), tokens only.
- **Built on every docs build** into `public/r` (not committed); no new dependencies. `e2e/registry.spec.ts` checks
  the files are served and the docs page lists every block.
- **Verified** by installing items into a fresh Next.js 15 + shadcn app: dependencies installed, files placed,
  production build passed, no hydration warnings, forms and toasts worked.
- **Later:** claim the `@plopui` namespace in shadcn's registry directory (a PR to shadcn-ui/ui), so
  `npx shadcn add @plopui/button` works.
